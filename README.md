# Incremental TCP Server

Reactorパターンの実装を目標とした、C++の学習用プロジェクトです。

最もシンプルなTCPソケットサーバーから始め、仕様の追加と設計のリファクタリングを繰り返しながら、インクリメンタルに開発しています。通信処理や複数クライアントへの対応を段階的に実装し、その過程で見えてきた課題を次の設計につなげていきます。

## 現在の実装

現在は、ノンブロッキングソケットを使い、単一スレッドのループで接続の受け付けと各クライアントの読み書きを順番に処理しています。

- IPv4のループバックアドレス（`127.0.0.1`）で待ち受け
- 複数クライアントの接続を保持し、各接続の読み書きを処理
- `EAGAIN` / `EWOULDBLOCK` に対応し、未送信のデータをバッファに保持
- `;` を区切りとする簡単な挨拶コマンドに応答
- `SIGINT`（Ctrl+C）または `SIGTERM` によるサーバーの終了

Reactorパターンはまだ実装途中です。現時点ではI/Oイベントを待つ仕組みがなく、処理できるデータがない場合もループを繰り返します。直近の開発ではCPU使用率がほぼ100%になることを確認しており、次は `select` / `poll` / `epoll` による待機の導入を検討しています。

## ビルド・実行方法

### 必要な環境

- Linux（`accept4` などのLinux向けAPIを使用）
- C++20に対応したC++コンパイラ
- Make
- AddressSanitizer / UndefinedBehaviorSanitizerを利用できる環境（Makefileで有効化）
- 接続確認用の `nc`（任意）

### ビルドと起動

```sh
make
./reactor 8080
```

ポート番号を引数に指定します。起動したターミナルで Ctrl+C を押すと終了します。

### 接続とコマンド

別のターミナルから接続します。

```sh
nc 127.0.0.1 8080
```

接続後、次のコマンドを入力してEnterを押します。コマンドの区切りは改行ではなく `;` です。

| 入力 | 応答 |
| --- | --- |
| `HELLO Itsuki;` | `hello, Mr.Itsuki!` |
| `HELLO;` | `hello, Sir.` |
| `BYE;` | `Good bye!` |

未対応のコマンドには、利用できるコマンドの案内を返します。`BYE;` は応答を返すだけで、接続やサーバーを終了するコマンドではありません。

## 現在の設計

サーバーの制御、通信処理、アプリケーションの処理を分離しています。

| ファイル | 役割 |
| --- | --- |
| [src/main.cpp](src/main.cpp) | サーバーの組み立て、シグナルハンドラの設定、起動 |
| [src/Server.hpp](src/Server.hpp) / [src/Server.cpp](src/Server.cpp) | `Server` による接続の管理とループ処理、`Client` による接続ごとの読み書きと送信バッファの管理 |
| [src/Transport.hpp](src/Transport.hpp) | 接続を受け付ける `ITransport` と、読み書きを行う `IByteStream` のインターフェース |
| [src/TCPTransport.hpp](src/TCPTransport.hpp) / [src/TCPTransport.cpp](src/TCPTransport.cpp) | TCPソケットによる各インターフェースの実装と、ソケットの解放 |
| [src/application_protcol.cpp](src/application_protcol.cpp) | 受信データの区切りの解析と、コマンドに応じた応答の生成 |

アプリケーションの処理は `RequestProcessor` としてサーバーに渡します。現在の起動処理では挨拶コマンドを扱う `mini_greeting_protcol` を使用しています。同じファイルにはエコー用の `echo_protcol` もあります。

## 今後の予定・現在の課題

次のステップは、I/Oイベントを待機する仕組みを導入し、Reactorパターンの実装へ進めることです。待機、イベントの振り分け、各イベントに対する処理をどう分離するかも検討していきます。

現在のコードには、次の課題も残っています。

- プロトコル処理の受信バッファが関数内の `static` 変数になっており、複数クライアント間で共有される
- 読み込み時に、データがまだ届いていない状態と接続終了をどちらも `0` として扱い、切断済みクライアントを一覧から取り除いていない

学習の進行に合わせて、これらの処理や設計も見直していきます。
